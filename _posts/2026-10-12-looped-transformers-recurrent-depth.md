## 一、先抛结论：一个 2018 年的老点子，被 2026 年的前沿模型重新捡了起来

最近 OpenAI 的 GPT-6 Astra 发布，除了「计算机操作（computer use）」能力的大跃进之外，技术圈讨论最多的，是一则来自 *The Information* 的爆料：Astra 可能用了一种叫 **「递归深度（recurrent depth）」或「循环 Transformer（looped transformer）」** 的技术，而且有人把它和「模型在隐藏自己的思维链」联系在了一起。

这件事值得认真讲清楚，因为它触到了当下大模型的一个核心矛盾：

> 想让模型更聪明，到底是该把它造得更「大」（更多参数、更多层），还是让它想得更「深」（同样的参数，反复多算几遍）？

循环 Transformer 给的答案是后者。它的核心思想一句话就能说明白：**把中间表示（hidden states）反复送进同一批 Transformer 块里走多遍，而不是只走一遍。** 关键在于——这几遍用的是**同一套权重**。

这个点子并不新，2018 年的 Universal Transformers 论文就提出来了。但在「堆参数」几乎走到物理与成本极限的 2026 年，它被重新发现、系统化，并很可能进了最前沿的闭源模型里。下面我们从原理一层层拆。

## 二、原理：什么是「循环」？从一个真实的开源模型讲起

### 2.1 最朴素的版本：把同一摞块走两遍

先看一个今年 7 月放出的开源权重模型 **Nanbeige4.2-3B**。它的结构乍看就是个普通 Transformer：输入文本 → tokenize → embedding → 过 22 个 Transformer 块 → 输出。每个块都有自己独立的权重。

不一样的地方在于那根「回头箭头」：走完 22 个块之后，隐藏状态会被**重新喂回这 22 个块的开头，再走一遍**。于是 block 1 又用一次、block 2 又用一次……一直到 block 22。

如果把这个过程「展开（unroll）」，你会得到 **44 次块运算（block applications）**。但和一个拥有 44 个不同块的常规 Transformer 相比，第二遍的 22 次运算**复用了第一遍的权重**：第 23 次运算用 block 1 的权重，第 24 次用 block 2 的权重，依此类推。

净效果是：**有效深度从 22 翻到了 44，但 Transformer 块的参数量只有一半。**（注意 embedding 层和输出层通常很大，这里不计入对比；在 Nanbeige 中它们约占 3B 参数的 25%。）

Nanbeige 的作者说，为什么是 2 遍而不是 3、4 遍？因为 2 遍是性价比最高的点——再增加循环虽然还能涨点性能，但额外算力不划算。而且他们还报告了两个有意思的工程结论：**从头训练这种循环结构，比把一个已经预训练好的常规模型「改造（upcycling）」成循环结构效果更好**；另外他们试过让两遍共享 KV 缓存，缓存是省了一半，但模型变差了，所以最终发布的版本是两遍各自独立缓存。

### 2.2 别误会：省的是参数，不是计算

这是最容易被标题党带偏的一点。循环**只省存权重的内存，不省计算**。

- 前向传播要实打实地过 44 次块运算；
- 训练时梯度要在两遍共享栈里都回传一遍；
- KV 缓存也省不了——虽然两遍权重相同，但第二遍进入块的中间表示不一样，产生的 K/V 也不一样，所以要分别缓存，缓存需求和 44 个不同块的常规 Transformer 一样。

所以更准确的说法是：**循环 Transformer 用「和大模型差不多的计算量」，换来了「只有一半的权重参数」。** 它压的是参数，不是算力。我的看法是：在显存（存权重 + 存 KV）日益成为瓶颈的今天，这种「拿计算换参数」的交易，恰恰踩在了很多部署场景的痛点上。

### 2.3 进阶：让循环次数「因 token 而异」

Nanbeige 固定走 2 遍，Universal Transformer 则更灵活——它反复应用的是**单个块**，而且循环次数可以不固定。论文引入了 **自适应停机（adaptive halting）**：用一个小的、可训练的函数，为每个位置、每一步输出一个「停机概率」，把这些概率累加，一旦超过阈值就停止循环（同时设一个最大循环数兜底）。

这样模型就能**把算力花在真正需要的 token 上**：简单的 token 可能只循环一两遍，难的 token 循环三四遍。ByteDance 的 **Ouro**（如 Ouro-Thinking 2.6B，把 48 个块的栈走 4 遍 = 192 次块运算）也借用了这种「学到的退出门 + 累积概率阈值」的思路。

### 2.4 再进阶：用「路由器」决定每个 token 循环几遍

2025 年的 **Mixture-of-Recursions（MoR）** 把这件事做得更精细。它和 Universal Transformer 一样让 token 过「递归块」一到多次，但**用一个小的、学到的路由器（router）来决定循环次数**——这和 Mixture-of-Experts（MoE）里的路由如出一辙，区别只是：MoE 路由决定「走哪个专家」，MoR 路由决定「把共享栈走几遍」。

路由器看的是 token 的隐藏表示（里面已经含了上下文信息），所以同一个词在不同位置、不同上下文下，循环次数可以不同。论文给了两种路由方式：

- **专家选择式（expert-choice）**：每一步递归自己挑要处理哪些 token，被挑剩的 token 提前退出；
- **token 选择式（token-choice）**：开头就一次性给每个 token 分配 1/2/3 遍的路径。

MoR 的实验结论很有代表性（见原论文的验证损失曲线）：**在最小的模型规模上，常规 Transformer 反而最好；但模型一旦够大，MoR 就追上甚至反超，尤其在训练算力预算较小时优势明显。** 这里还有个隐藏红利——通过跳过部分计算，MoR 在相同算力预算下能处理更多 token。

我的看法：这条曲线提醒了一个常被忽视的教训——**小规模实验会骗人**。如果只看 135M 的小模型，你会得出「循环没用」的相反结论。架构创新必须在足够大的规模上验证，这也是为什么这类研究越来越只有大机构玩得起。

## 三、它和 RNN 是什么关系？

有深度学习背景的人看到「循环」会立刻想到 RNN。两者确实都「复用权重」，但复用的**维度不同**：

- **RNN** 跨**时间步**复用权重——读一个词、更新隐藏状态、再读下一个词，信息沿序列向前传递；
- **循环 Transformer** 跨**网络深度**复用权重——同一个 token 的中间表示在块栈里上上下下走好几遍，token 之间的信息仍然靠注意力来传。

如果觉得这个类比绕，有个更简单的理解：**循环 Transformer ≈ 带权重共享的「变大」**。

## 四、关键问题：Astra 真用了吗？它和「隐藏思维链」有关吗？

这是整件事情里最需要「区分事实与猜测」的部分。

**第一，Astra 到底用没用？** 目前只有 *The Information* 的爆料，没有官方确认。模型不开源，无法自行核验。OpenAI 首席科学家 Pachocki 说过「我们当前前沿模型（含 Astra）的计算图深度与 GPT-4 相比在 2 倍以内」——但这句话既可以解释成循环，也可以解释成「单纯多堆了一倍常规块」。Raschka 的判断（我也认同）是：**Astra 大概率用了循环 Transformer 的某些要素**（有爆料、技术本身有前景、首席科学家的措辞也吻合），但 **Astra 之所以强，主因更可能是训练配方和训练数据的改进，循环顶多算锦上添花**，*The Information* 高估了它的贡献。

**第二，循环会「隐藏」思维链吗？** 答案基本是否定的，这里有两层澄清：

1. **对终端用户没区别**：OpenAI 从 o1 开始就一直对用户隐藏大部分推理轨迹，这不是新鲜事。
2. **「推理变短」≠「变得不可解释」**：有人担心——模型在架构内部多算了（循环），是不是就不需要那么多外部「思考 token」了，于是思维链变短、变得难以监督？从数据看，Astra 在固定准确率下确实比前代 GPT-5.6 Sol 用更少 token，但这更可能只是**模型更强、一次做对、少走弯路**的副作用。就像同一家族里，更大的 Sol 本来就比更小的 Luna 用更少 token（Luna 在相近性能下要多用约 80% 的 token），你不会因此说 Sol「更不可解释」。

Pachocki 本人也专门发声澄清，大意是：不要被「混乱的报道」带进一场「冲向不可监督性」的竞赛；思维链监控（CoT monitoring）确实脆弱、且在往不好的方向走，但原因**不在于架构变化**，OpenAI 一直在努力保住这项能力。

我的看法：真正值得担心的，不是「循环导致思维链变短」，而是**「推理轨迹本来就不保证忠实反映模型内部到底在想什么」**这个更根本的问题。循环只是把更多计算搬到了「说出来之前」，它既没有特别加剧、也没有解决可解释性难题。把架构当成替罪羊，反而会让我们忽略真正的对齐风险。

## 五、循环到底值不值？——几篇新论文给的硬证据

光讲故事不够，看几个把问题做实的研究：

- **潜在推理 / 递归深度（Geiping et al., 2025）**：训了个 3.5B 模型（800B token），把一摞共享块夹在「2 个初始块 + 2 个末端块」中间，而且每一遍都把初始块的输出重新拼进来再过共享栈。亮点是**训练时随机采样循环次数**，于是推理时可以由使用者自由指定预算（8/32/64 遍），还带一个基于 KL 散度的自适应停机。结论：**收益因任务而异**——HellaSwag 过了约 8 遍就饱和，而 GSM8K、HumanEval 能从更多循环里持续获益。这意味着「想多久」可以变成一个**推理时的旋钮**。
- **记忆 vs 推理的分离（Beyond Parameters, 2025-06）**：把「存信息」和「用信息解题」分开测。结论很干净——**循环几乎不增加模型能存的知识量**（存知识靠参数量），**但循环能实实在在提升多步数学等推理任务的表现**。一句话：循环是「算」的机制，不是「存」的机制。
- **同算力预算下的公平对比（SMELT, 2026-09）**：这是最关键的一篇。它在**每 token 算力、非 embedding 参数、KV 缓存都大致对齐**的条件下，用 MoE 架构把中间一半的块走两遍（并相应收窄隐藏维、补专家、调注意力头来保持各项预算可比），一路 scaling 到 54B 非 embedding 参数。结论：**要达到同样的验证损失，SMELT 大约能省 6.8%–18% 的训练算力。** 也就是说——**在相同算力下，循环能换来一个略好的模型。**
- **全带宽 Transformer（Full-bandwidth Transformer, 2026-08）**：研究跨 token 位置的循环（把上一个 token 的最终隐藏状态经一个学到的门，和新 token 的 embedding 融合，作为下一次前向的输入）。在 1B 基座上，这种潜在反馈能在 MATH500 上输出**更短的推理轨迹**同时维持或提升准确率——但有个重要警示：**这个「变短」效应在指令微调之后就消失了**，而且也没证明更短的轨迹是否更不忠实。

把这几篇串起来看，循环 Transformer 的「性价比问题」基本有了答案：**在模型足够大、算力对齐的前提下，它确实能用同样的预算换来更好的模型；它增强的是「推理/计算」能力，而不是「记忆/知识」容量。**

## 六、横向对比：循环 vs 堆层 vs MoE vs 长思维链

| 方案 | 核心做法 | 主要换来什么 | 主要代价 | 适合场景 |
| --- | --- | --- | --- | --- |
| 堆更多层 | 增加不同权重的块 | 更强表达力 + 更多知识容量 | 参数、显存、训练成本全涨 | 不差钱、追绝对性能 |
| **循环 Transformer** | 同一批块反复走多遍 | 更深的「计算/推理」，参数砍半 | 计算与 KV 缓存不省 | 显存受限、要强推理 |
| MoE | 多专家稀疏激活 | 参数量巨大但激活算力小 | 显存占用高、路由与负载均衡复杂 | 超大模型、重知识 |
| 长思维链（显式推理） | 生成更多中间 token | 用「文字草稿纸」换对错 | 延迟、token 成本高 | 需要可读、可审计的推理 |

我的看法：这四者并非互斥，趋势反而是**融合**——SMELT 本身就是「MoE + 循环」。可以这样理解它们的分工：**MoE 管「宽」（容量、知识），循环管「深」（计算、推理），显式思维链管「可读与可审计」。** 未来的强模型很可能是三者的某种配比，而「循环几遍」会和「思考几个 token」一样，成为推理时可调的预算维度。

## 七、优缺点小结

**优点**

- **参数效率高**：有效深度翻倍，权重只要一半，省的是存权重的显存。
- **推理能力增益明确**：多篇论文一致显示它能提升多步推理，且在同算力下略优于常规结构。
- **弹性计算**：循环次数可做成自适应（按 token 路由）或推理时可调（预算旋钮），把算力花在刀刃上。
- **与现有生态兼容**：仍是标准 Transformer 块 + 注意力 + KV 缓存，不需要推倒重来。

**缺点与坑**

- **不省计算、不省 KV 缓存**：延迟和推理成本并不会因为「参数少」而下降。
- **规模依赖强**：小模型上可能不如常规结构，必须大规模验证，研究门槛高。
- **训练更不稳定**：循环遍数越多，训练越慢、优化越难；且从头训比改造预训练模型更好，迁移成本高。
- **收益看任务**：对知识型任务几乎无益，主要帮推理型任务。
- **可解释性话题容易被误读**：它和「隐藏思维链」没有强因果，但很容易被爆料和标题党绑在一起制造恐慌。

## 八、给读者的可落地收获

1. **理解「深度」有两种**：参数深度（堆不同的块）和计算深度（同一批块多走几遍）。以后看到「某模型计算图深度是 GPT-4 的 2 倍」这类表述，先想一想它指的是哪一种。
2. **把「想多久」当成可调预算**：如果你在用支持 reasoning effort / 思考档位的模型（low/medium/high 等），本质上就是在调「测试时计算」。对难题（数学、复杂代码）调高、对简单任务调低，往往比换模型更划算——这与循环论文里「GSM8K 受益于更多循环、HellaSwag 很快饱和」的规律一脉相承。
3. **别迷信「推理轨迹变短 = 更强」**：短可能是因为更强（少走弯路），也可能是因为少写了关键步骤。当你需要可审计的推理时，宁可要更长但更忠实的思维链。
4. **做模型/做架构的人**：如果你显存受限但想要更强推理，循环（尤其是 MoE+循环，如 SMELT 的思路）值得作为堆层之外的严肃选项评估；但务必在目标规模上做对照实验，小规模结论会误导你。
5. **关注「计算机操作（computer use）」这条线**：Astra 这次真正的大跃进其实在这里（OpenAI 甚至买了大量 Mac Mini/Studio 作为训练环境让模型学用 macOS）。我的判断是，接下来一段时间，开源与闭源的竞争焦点会从「写代码/用 API」扩展到「用图形界面操作软件」，而这对普通人用 AI 做日常电脑任务的意义，可能比架构内卷更大。

## 结语

循环 Transformer 不是什么魔法，它是一个被重新发现的、朴素而有效的工程权衡：**用计算换参数，用深度换聪明。** 它既不像爆料里说的那样神秘到能「藏起思维」，也不是可有可无的小花招——在算力对齐的严肃对比下，它确实能挤出 7%–18% 的训练算力红利。

我更愿意把它看成一个信号：**大模型的进步，正在从「无脑变大」转向「更会分配计算」。** 当模型学会在心里多想几遍、并且知道什么时候该多想、什么时候一遍就够，这件事本身，就比参数表上的数字更接近「智能」的样子。
