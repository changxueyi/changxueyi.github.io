> 本文基于 Orca 官方仓库（github.com/stablyai/orca）与官网 onorca.dev 的公开信息整理，并加入了我个人的分析与判断。事实与观点会尽量区分开来。

## 一、先说一个新词：ADE

我们都熟悉 **IDE（Integrated Development Environment，集成开发环境）**——VS Code、JetBrains 这类工具，服务的对象是"写代码的人"。

而 **ADE（Agent Development Environment，智能体开发环境）** 是最近冒出来的新提法，服务对象变了：不再是你亲手敲每一行代码，而是"指挥一群 AI 智能体替你干活的人"。Orca 就是把 ADE 做成产品的代表之一。

一句话对比：

> IDE 让一个人把代码写好；ADE 让一个人把一支智能体舰队管好。

这个视角的转变，正是我想重点讲的东西。

## 二、Orca 是什么（事实层）

| 项目 | 信息 |
| --- | --- |
| 定位 | 面向并行智能体舰队的开发环境（The ADE for a fleet of parallel agents） |
| 出品方 | Stably AI（YC 投资） |
| 开源许可 | MIT（完全开源、可自由使用） |
| 主要语言 | TypeScript |
| 形态 | 桌面应用（含手机端 Companion） |
| 官网 / 仓库 | onorca.dev ／ github.com/stablyai/orca |
| 社区热度 | GitHub star 数已达 8 万+（截至 2026-09） |

它的 Slogan 很直白：**"The AI Orchestrator for 100x builders"**——把 Codex、Claude Code、OpenCode、Pi 等编码智能体并排跑起来，每个 agent 待在自己独立的 git worktree 里，全部集中在一处管理。

## 三、核心能力拆解

我把官方功能清单归了类，能更清楚看出它到底在解决什么：

**1. 并行 Worktrees（灵魂功能）** —— 把同一个 prompt 一次扇出给多个 agent，每个在隔离的 git worktree 里独立干活，最后横向比较、把最好的合并回来。用 git worktree 做隔离，天然避免多个 agent 互相踩踏。

**2. 多 Agent 并存，用你自己的订阅** —— 不绑定某一家模型，Codex / Claude Code / OpenCode / Pi 都能接，用你自己的账号和额度跑；内置账号切换与用量追踪。

**3. Terminal Splits** —— Ghostty 级别的 WebGL 终端，支持无限分屏、重启后保留 scrollback。

**4. Design Mode（我最喜欢的一个）** —— 在真实 Chromium 窗口里点选任意 UI 元素，直接把它的 HTML、CSS 和一张裁剪截图塞进 agent 的 prompt。做前端时，"我说的就是这个按钮"终于不用靠嘴描述。

**5. GitHub & Linear 原生集成** —— 应用内浏览 PR、Issue、看板，从任意任务直接开 worktree，评审不用来回切上下文。

**6. SSH Worktrees** —— 把 agent 跑在远程高配机器上，本地照样有完整的文件编辑、git 和终端，自动重连 + 端口转发。

**7. Annotate AI Diffs** —— 在 diff 任意行写评论，直接回传给 agent 让它改，审阅、修改、提交都不离开 Orca。

**8. Orca CLI + Computer Use** —— `orca worktree create`、`snapshot`、`click`、`fill` 等命令让 agent 自己也能驱动 Orca；配合 Computer Use，agent 需要时还能操作桌面应用与可见 UI。

**9. Mobile Companion** —— 手机上监控和指挥 agent，跑完收到通知，随时随地发追问。

此外还有 Quick Open（跨 worktree/文件/agent/命令的全局搜索）、Markdown/图片/PDF 预览、通知与未读状态等一堆细节。

## 四、ADE 到底带来了什么好处（分析层）

抛开功能清单，我认为 Orca 这类 ADE 真正的价值在四个层面：

**① 把"串行等待"变成"并行赛马"。** 过去用单个 AI 编码工具，你发需求、等它做完、不满意再重来，是串行的。ADE 的并行 worktree 让你一次派 5 个 agent 同做一件事，再挑赢家。AI 生成本就有随机性，"多跑几次取最优"从奢侈变成默认工作流——这是我认为最本质的改变。

**② 用 git worktree 解决了"多 agent 打架"的老大难。** 多个 agent 同改一个仓库最怕互相覆盖。Orca 用 worktree 做物理隔离，既能并行又能干净合并。这个选择很"工程师"，说明它是给认真做工程的人用的，不是玩具。

**③ 人从"作者"变成"评审官 + 编排者"。** Annotate Diff、Design Mode、GitHub/Linear 集成，本质都在强化一件事：你的时间该花在"审阅和决策"上，而不是敲样板代码。这与我自己做 AI Agent 的体感一致——瓶颈正从"写得多快"转向"审得多准、编排得多好"。

**④ 不锁定模型，保住主动权。** 支持多家 agent、用自己的订阅、MIT 开源，意味着你不会被某家厂商绑死。在模型能力半年一变的今天，这种"编排层中立"的定位，比押注某个具体模型更稳。

## 五、和"IDE + 单 Agent 插件"比，差在哪

- **IDE + Copilot / 单 agent**：以"文件和光标"为中心，AI 是辅助补全，一次基本服务一个任务。
- **ADE（Orca）**：以"任务和 agent"为中心，AI 是主力，一次编排多个任务/多个 agent，人做裁决。

说白了，前者是"给人配一个 AI 助手"，后者是"给人配一个 AI 团队"。当手上的活儿能拆成很多相对独立的小任务时，后者的效率上限明显更高。

## 六、适合谁 / 不适合谁（我的看法）

**适合：** 需要同时推进多个功能/多个仓库的资深开发者、技术 leader；愿意把自己定位成"编排者与评审者"的人；已经在用 Codex / Claude Code、想统一管起来的人。

**可能暂时不适合：** 刚学编程、需要自己一行行理解代码的新手（并行 agent 会放大"看不懂却合进去了"的风险）；任务高度耦合、难以拆成并行小块的场景。

## 七、我的判断：ADE 是会长期存在的新品类

我个人观点是：ADE 不是噱头，而是 Agent 时代顺理成章的基础设施。

理由有三：一是单个 agent 能力还不稳定，"多路并行 + 择优"在可预见的将来都有价值；二是当 agent 产出越来越多，人的注意力会成为最稀缺资源，而 ADE 正是为"节省人的注意力"而生的编排层；三是它站在模型之上、保持中立，抗住了底层模型频繁更迭的风险。

当然也有隐忧：并行跑多个 agent 的成本与算力开销不低；"择优合并"依赖人的判断力，审阅跟不上就会把问题合进主干；多家 agent 各自的账号、隐私与代码外发也需谨慎对待。

但方向上，我认为"从 IDE 到 ADE"和当年"从记事本到 IDE"是同一种演进——工具不断把人从重复劳动里解放出来，让人专注在判断和创造上。Orca 用 8 万 star 证明了这个方向的需求是真实的。

## 八、想上手

- 官网：onorca.dev
- 开源仓库：github.com/stablyai/orca（MIT，可自建自用）
- 建议玩法：先拿一个能拆成多个独立小任务的项目，用"一个 prompt 扇出多个 agent → 比较 → 合并赢家"跑一遍，最能体会 ADE 与传统工具的差别。
