## 一、先抛结论：文本生成第一次有了「真正的第二条路」

如果你在过去两年用过任何一个大模型，你其实一直在用一个隐藏假设：**语言模型 = 自回归（Autoregressive, AR）模型**。也就是说，模型从左到右、一个 token 接一个 token 地生成，第 $t$ 个 token 依赖前 $t-1$ 个 token：

$$
p(x) = \prod_{t=1}^{N} p(x_t \mid x_{<t})
$$

这个假设强到几乎没人质疑它——GPT、Claude、Llama、Qwen，全是这么做的。它带来两个结构性后果：**生成延迟随长度线性增长**（N 个 token 就要 N 次串行前向），以及**从左到右的因果掩码**（每个 token 只能看到左边的信息，天然无法「回头改前面」）。

扩散语言模型（Diffusion Language Model, 常简称 Diffusion LLM / dLLM）做的事情，是把这两条同时推翻：

> 不再一个 token 一个 token 地吐，而是**先把整段文本初始化成一片「噪声」，再用少数几步迭代，把噪声并行地「去噪」成一句完整的话**。

这听起来像图像生成（Stable Diffusion 就是这么干的），而这正是它的思想来源：既然图像扩散能并行出整张图，文本为什么不行？2025 年 LLaDA 第一次把这个问题用「从零训练一个 8B 扩散语言模型」的方式回答得比较硬气——它在多项基准上与自回归基线打平，甚至在指令跟随上表现不错。2026 年的 iLLaDA 则把它推到了 12T token 的预训练规模，并换成**完全双向注意力**，在 BBH、ARC-Challenge 等基准上大幅反超原始 LLaDA。

所以现在的状态是：**扩散 LLM 不再只是「玩具」，但它也还没到「替代自回归」的程度**。这篇文章要讲清楚的，就是它到底解决了什么、代价是什么、以及你现在该怎么用它。

## 二、背景与动机：为什么有人非要绕开自回归？

### 2.1 自回归的两个「原生缺陷」

**缺陷一：串行 = 延迟。** 生成一个 1000 token 的回答，无论你的 GPU 多强，都要跑 1000 次前向（每次吐一个 token）。KV-Cache 让每次前向变便宜，但**串行次数无法压缩**。这就是为什么长输出的首字延迟和总时延始终下不来，也是为什么工业界要发明投机解码（speculative decoding）——本质是想办法一次多「猜」几个 token。

**缺陷二：因果掩码 = 单向。** 每个 token 只能看到左边。这在做「填空」「改写中间某句」「代码补全的中间插入（infilling）」时非常别扭——你得把整段重写一遍。语言任务里大量需求其实是**双向的、可编辑的**，自回归却只能「单向追加」。

### 2.2 一个被忽视的类比

图像/视频生成已经证明：**「迭代去噪 + 并行」是一个和「自回归」完全不同的、可行的生成范式**。2023 年以来，研究者一直在问同一个问题：文本是离散的 token 序列，能不能也套上这套范式？

早期尝试（D3PM、Diffusion-LM 等）大多停留在小规模、且质量明显不如自回归。真正的转折点在 2025 年：**LLaDA 证明「用掩码扩散 + 从零预训练」可以做到 8B 规模并追平自回归基线**。这才让「扩散 LLM」从一个学术 curiosities 变成了前沿赛道。

## 三、技术原理：掩码扩散语言模型是怎么工作的

要理解扩散 LLM，抓住一条主线：**前向加噪 → 反向去噪 → 训练一个「去噪器」**。文本的「噪声」不是高斯噪声，而是**掩码（[MASK]）**。

### 3.1 前向过程：把一句话「逐级掩掉」

给定真实文本 $x_0$，前向过程在 $t \in [0,1]$ 上逐步把 token 替换成 [MASK]。到 $t=1$ 时，整句全是 [MASK]。这一步是**预先定义、无需学习**的，和图像扩散里的加噪完全对应，只是「噪声」变成了离散的掩码。

### 3.2 反向过程：训练一个 Transformer 预测被掩掉的 token

反向生成是模型要学的部分：给定一个**被随机掩码**的序列，让 Transformer 预测每个 [MASK] 位置原本是什么 token。训练目标就是掩码语言建模（MLM）式的交叉熵，只不过掩码比例是随 $t$ 连续变化的：

$$
\mathcal{L}(\theta) = -\,\mathbb{E}_{t,\,x_0,\,x_t}\Big[\sum_{i:\,x_t^i=[\text{MASK}]} \log p_\theta\big(x_0^i \mid x_t\big)\Big]
$$

LLaDA 的论文特别强调：这套目标其实是在优化**一个似然下界（likelihood lower bound）**，因此它在理论上是一个「有原理的生成式模型」，而不是拼凑的启发式。这一点很关键——它说明扩散 LLM 不是「用 BERT 硬凑生成」，而是有独立的概率建模框架。

### 3.3 采样：从全 [MASK] 到完整文本，只要几步

生成时从「整句全 [MASK]」出发，反复：

1. 让模型对所有 [MASK] 位置**同时**预测分布；
2. 按某种策略（例如「置信度最高的位置先定稿」）**只揭开一部分**位置；
3. 重复若干步，直到所有位置都被填上。

因为**所有位置是并行预测的**，如果只用 $K$ 步就能收敛，那么生成 $N$ 个 token 只需要 $K$ 次前向，而自回归需要 $N$ 次。当 $K \ll N$ 时，**这是数量级上的并行优势**——也是扩散 LLM 最大的卖点。

> **关键洞察**：扩散 LLM 把「生成」从一个**串行解码问题**变成了一个**迭代精修问题**。前者每一步都必须正确才能继续；后者允许「先粗糙地全填一版，再逐步修正」，天然支持双向上下文和任意顺序生成。

### 3.4 2026 年的新进展：连续扩散与「设计空间」

除了 LLaDA 这种**离散掩码扩散**，还有一条路线是**连续扩散语言模型（CDLM）**——把 token 嵌入到连续空间，用流匹配/扩散去噪，采样更快、可控性更好。2026 年 10 月的论文《On the Design Space of Continuous Diffusion Language Models》专门研究两个关键旋钮：

- **自条件（self-conditioning）**：让模型在去噪时参考自己上一步的预测。论文发现它的作用其实是**纠正训练/推理不匹配**——训练时模型很少见到「推理时那种半成品状态」，自条件把这些状态补上。更妙的是，作者提出一种**两级插值（two-level interpolant）**，不额外增加一次前向就能拿到同样的收益。
- **嵌入几何（embedding geometry）**：token 嵌入在连续空间里怎么摆放，直接影响去噪难度，进而决定能不能用更少步数。

这类工作说明：扩散 LLM 的研究重心，正在从「能不能做」转向「**怎么用更少步数、更稳地做**」——也就是工程落地最关心的问题。

## 四、与同类方案对比：扩散 LLM 站在哪一格？

| 维度 | 自回归 LLM | 离散扩散 LLM（LLaDA/iLLaDA） | 连续扩散 LLM（CDLM） | 投机解码（AR 的补丁） |
|---|---|---|---|---|
| 生成顺序 | 严格左→右 | 任意顺序 / 并行 | 任意顺序 / 并行 | 仍是左→右 |
| 前向次数 | N（随长度线性） | K 步（K≪N 时更快） | 步数可更少 | N 但每步多吐 |
| 上下文方向 | 因果（单向） | 双向 | 双向 | 因果（单向） |
| 天然能力 | 续写 | 填空/改写/infilling | 填空/改写/可控生成 | 续写 |
| 生态成熟度 | 极高（KV-Cache、vLLM、量化…） | 中低 | 低 | 高 |
| 质量现状 | 天花板最高 | 接近同规模 AR，仍略逊 | 研究中 | 无损（本质是 AR） |

几条要点：

- **投机解码不是同类替代，而是 AR 的加速补丁**。它保留自回归的正确性，靠「小模型草稿 + 大模型验证」提速，但无法摆脱串行本质。扩散 LLM 是**换范式**，投机解码是**打补丁**——两者动机相同（降延迟），手段不同。
- **离散 vs 连续扩散**：离散（掩码）扩散和现有 Transformer/分词器生态兼容性好，是 LLaDA 路线；连续扩散理论更优雅、可控性和步数效率可能更好，但和「token 是离散符号」这件事存在根本张力，工程上更麻烦。
- **Block Diffusion（BD3-LM，2025）**：折中方案——把序列切成块，**块内用扩散并行、块间用自回归串行**。它试图同时拿到「并行吞吐」和「自回归的可扩展性」，是当前很务实的一条路。
- **和 Mamba/SSM 的区别**：状态空间模型也是非 Transformer 路线，但它们解决的**主要是长序列的效率**，生成方式仍是自回归；扩散 LLM 改的是**生成范式本身**，两者正交，理论上可以叠加。

## 五、真实进展盘点（2025–2026）

- **LLaDA（2025-02，arXiv:2502.09992）**：8B 掩码扩散模型，**从零预训练 + SFT**，前向加掩码、反向生成，优化似然下界。论文声称在通用/数学/代码基准上与自建 AR 基线相当，8B 版在 in-context learning 上可与 LLaMA3 8B 竞争。这是「扩散 LLM 能上规模」的里程碑。
- **iLLaDA（2026，arXiv:2606.25331）**：8B，**完全双向注意力**，预训练扩到 **12T token**，指令语料 25B token 训 12 个 epoch，并引入变长生成与基于置信度的选择题评分。相比 LLaDA 全面提升（论文举例 BBH +21.6、ARC-Challenge +14.9）。它证明**扩散目标 + 双向注意力可以一直用到大规模**，而不是只在预训练后段切换到 AR。
- **Mercury（Inception Labs，2025）**：较早的商业化扩散 LLM，主打**极高生成速度**（宣称在 H100 上可达上千 token/s），面向代码等场景。
- **Gemini Diffusion（Google DeepMind，2025 实验版）**：官方演示强调**低延迟**（宣称约 1479 token/s），用于验证扩散范式在大模型上的可行性。
- **Dream 7B（HKU + 华为诺亚，2025）**：开源离散扩散模型，支持**任意顺序生成**，在填空/规划类任务上展示出 AR 不具备的灵活性。
- **2026-10 连续扩散设计空间论文**：如上所述，聚焦自条件与嵌入几何，目标是**用更少步数、更省算力**地训练 CDLM。

> 提醒：Mercury、Gemini Diffusion 的速度数字是厂商/官方演示口径，硬件、batch、评测方法不同会差很多，**不能直接横向对比**。把它们当成「方向正确、量级可信」的信号，而不是精确排名。

## 六、应用场景：它在哪儿真的有用？

1. **低延迟交互**：聊天、语音助手、实时字幕等场景，扩散 LLM 的并行特性可能把总时延压下来——**如果** $K$ 步足够小、单步并行利用率足够高。
2. **文本填空与编辑（infilling）**：代码中间插入、文档局部改写、模板填充。这是双向模型的主场，自回归做起来很别扭。
3. **可控生成**：扩散的迭代结构天然适合在每一步注入约束（长度、格式、关键词、结构化输出），可控性可能优于自回归。
4. **结构化/规划类任务**：数学推理、代码补全、蛋白质序列设计等「需要全局一致、允许反复修正」的任务。
5. **批量吞吐型服务**：在固定 $K$ 步下，吞吐可能显著高于串行解码，适合离线批处理（如批量数据标注、合成数据生成）。

## 七、优缺点清单

**优势**

- 生成延迟有望从「线性于长度」降到「近似常数（K 步）」，**并行度高**；
- **双向上下文**，天然支持填空、改写、任意顺序生成；
- 理论上有独立的概率建模框架（似然下界），不是硬凑；
- 可控性、可编辑性潜力大。

**劣势与风险**

- **质量仍有差距**：同规模下，多数报告显示扩散 LLM 尚未全面超越成熟自回归模型，尤其在长程一致性和复杂推理上；
- **步数—质量权衡**：步数太少质量塌，步数太多并行优势被吃掉，调参敏感；
- **生态不成熟**：没有自回归那样成熟的 KV-Cache、PagedAttention、vLLM 式推理栈，量化、长上下文、工具调用等配套都在补课；
- **硬件利用率**：并行去噪对 batch/显存的要求与自回归不同，实际吞吐未必线性受益；
- **评测口径混乱**：速度数字可比性差，容易产生误导。

## 八、我的看法：它会是「第二范式」，而不是「替代品」

**我的看法**：扩散 LLM 目前最像的，不是「下一个 GPT」，而是「**文本生成领域的第二个基础范式**」。就像数据库里关系型和键值型长期共存、各自有主场，我判断未来更可能是**混合格局**：

- 需要**极低延迟、强编辑性、可控输出**的场景（实时交互、代码 infilling、结构化生成），扩散/块扩散会占据一席之地；
- 需要**最强推理与长程一致性、且生态最成熟**的场景，自回归仍会长期主导；
- 最现实的赢家可能是**块扩散（Block Diffusion）这种混合体**——既拿到并行吞吐，又保留自回归的可扩展性，工程上最不激进。

我还想强调一个容易被忽视的点：**扩散 LLM 真正的长期价值，可能不在「更快」，而在「可编辑」**。自回归模型的「只能追加、不能回头」是很多产品体验别扭的根源。一个能双向、能局部重写、能任意顺序生成的文本模型，会解锁今天很难做的交互形态（比如「帮我把第三段的语气改正式，但别动事实」）。速度只是它最容易被量化的卖点，**可编辑性才是它更难被替代的护城河**。

另外一个冷思考：**别被「并行 = 快」冲昏头**。并行去噪的每一步都要跑整个序列的全注意力，单步成本比自回归的一步高得多。只有当「步数 K × 单步成本 < 长度 N × 单步成本」时才真划算。很多演示的「1000+ token/s」是在特定硬件、特定 batch 下的理想值，换成你的实际负载可能打骨折。**任何速度宣称，都要在自己的数据上复现才算数。**

## 九、给读者的可落地上手建议

1. **先跑通再判断**：从 Hugging Face 上的 `GSAI-ML/LLaDA-8B-Instruct` 或 `GSAI-ML/iLLaDA-8B-Instruct` 开始，用官方 demo 做一次「填空 / 改写 / 续写」对比，亲手感受双向生成和自回归的差别。
2. **关注三条技术线**：① 掩码离散扩散（LLaDA/iLLaDA）；② 连续扩散（CDLM，关注步数效率）；③ 块扩散（Block Diffusion，最可能先落地）。跟踪它们的采样步数、质量与推理栈进展。
3. **用对场景**：把扩散 LLM 优先试在**填空、改写、可控生成、批量吞吐**上，而不是硬拿它去做最强推理——那是自回归的主场。
4. **自建评测再采信**：对任何「速度提升 X 倍」的宣称，用自己的 prompt 分布、自己的硬件、自己的质量指标复现一遍，重点看 **K 步下的端到端时延和吞吐**，而不是论文里的理想值。
5. **别急着迁移生产**：如果你的产品重度依赖 KV-Cache、长上下文、工具调用和多轮记忆，扩散 LLM 的配套还在补课，现阶段更适合作为**实验性能力**而非主力引擎。

## 十、结语

扩散语言模型用了两年时间，从「学术好奇」走到了「能和自回归掰手腕」。它最大的意义，不是今天就能打败 GPT，而是**证明了文本生成不止一条路**。当一个领域第一次出现「范式层面的第二条路」，往往意味着接下来几年会有大量工程创新发生在这条路上——推理栈、量化、长上下文、工具调用，都会被重新发明一遍。

对做产品的人：现在就该盯住它，尤其是**可编辑生成**这条线。
对做研究的人：**步数效率**和**质量追平**是接下来最值得攻的两个问题。
对普通使用者：**先知道有这条路**，在遇到「低延迟」「局部改写」这类需求时，记得它不是只有自回归一个答案。
