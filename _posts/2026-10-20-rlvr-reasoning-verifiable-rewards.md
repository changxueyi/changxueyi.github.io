## 一、背景与动机：为什么推理模型都在用 RLVR

2024 年底到 2026 年，大模型最明显的能力跃迁发生在「会不会推理」上——面对竞赛数学、复杂代码、多步逻辑，新一代模型会先写一长串「思考过程」再给答案，正确率大幅提升。OpenAI o1、DeepSeek-R1、以及后续一众开源推理模型，背后那条真正拉开差距的训练路线，就是本文的主角：**RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励的强化学习）**。

要理解它为什么重要，先回忆一下此前主流的 RLHF（基于人类反馈的强化学习）有什么痛点：

- **要训一个奖励模型（Reward Model）**：先让人类对一堆回答两两比较打分，再拟合出一个神经网络去模仿人的偏好，最后用它当奖励信号做 PPO。
- **奖励是「软」的、会被钻空子**：奖励模型本身不完美，策略模型很容易学会讨好它（reward hacking）——话说得漂亮、格式工整，但推理其实是错的。
- **贵且难扩展**：人工偏好数据昂贵，奖励模型会随策略漂移而失准。

RLVR 的核心洞察非常朴素却极其有效：**在数学、代码这类领域，答案的对错是可以自动、客观地验证的**。数学题可以核对最终数值，代码可以跑单元测试。既然如此，为什么还要一个会被钻空子的奖励模型？直接把「验证器判对不对」当成奖励（对 = 1，错 = 0）就好了。

这就带来三个决定性好处：**奖励不可伪造**（答案错了再漂亮也是 0 分，几乎杜绝了针对奖励模型的 hacking）、**几乎零标注成本**（有标准答案或测试用例即可，不需要人逐条打分）、**可无限扩展**（题库和自动判题可以海量生成）。DeepSeek-R1-Zero 甚至证明了：**完全不做监督微调、直接在基座模型上做 RLVR，也能自发涌现出反思、验算、换思路等推理行为**。这是 2025 年最震撼的结果之一，也是今天几乎所有推理模型都走 RLVR 路线的直接原因。

## 二、技术原理：从 PPO 到 GRPO，再到「组内相对优势」

RLVR 本质是一个策略优化问题：把 LLM 看成策略 $\pi_\theta$，输入一道题（prompt），它生成一条完整的「思考 + 答案」轨迹，验证器给出 0/1 奖励，用策略梯度去提升「能拿到奖励」的轨迹的概率。难点在于**信用分配（credit assignment）**：奖励只在轨迹末尾出现一个标量，怎么把它分摊回几千个 token？

**经典做法 PPO** 需要再训一个价值网络（critic）去估计每个状态的期望回报，用它算优势函数。但对动辄上万 token 的长推理，critic 又大又难训、还占显存。

**GRPO（Group Relative Policy Optimization）** 是 DeepSeek 系列带火的简化方案，也是今天 RLVR 的事实标准，思路很聪明——**用一组采样代替价值网络**：

1. 对同一道题，采样一「组」（比如 8～16 条）rollout；
2. 每条用验证器打 0/1 分；
3. 把这一组的奖励做标准化：$A_i = (r_i - \text{mean}) / \text{std}$，作为该条轨迹的「组内相对优势」；
4. 把这个优势**广播到该轨迹的每一个 token**上，做策略梯度更新。

好处是**彻底扔掉了 critic**，训练更轻、更稳。代价是两个会反复出现的结构性问题，恰好就是 2026 年这批新工作围攻的焦点：

- **信用分配太粗**：一整条轨迹里对的、错的、绕路的步骤被打了同一个分，模型学不到「究竟是哪一步想对了」。
- **组内信号会塌缩**：如果一组 rollout 要么全对、要么全错，相对优势就全是 0——这一组白采了。这在题太简单或太难、或采样多样性不足时经常发生。

> 把图的左半边对照着看：Policy → 采一组 rollout → 验证器判 0/1 → 组内相对优势 → 更新权重，再回到 Policy。整条链路里没有奖励模型、没有人工标签——这正是 RLVR 又便宜又抗造的根源，但「一个末端标量摊给上万 token」也正是它所有麻烦的源头。

## 三、2026 年 10 月的真问题：RLVR 到底加了什么？

把这批最新论文摆在一起看，它们其实在合力回答一个比「刷榜」更根本的问题：**RLVR 带来的提升，是教会了模型全新的推理能力，还是只是把基座模型本来就藏着的能力更可靠地激发出来？** 这不是文字游戏，答案直接决定你该把算力花在哪。

### 3.1 一个让人警醒的测量：差异只在约 4% 的 token

*What RL Brings to Reasoning*（arXiv:2610.24663）做了我最近读到最锋利的一个实验。他们拿 Qwen3-4B 的**基座版和 RL 版**对比，在 120 道 AIME 竞赛题上做「生成期干预」：只在**两个模型贪心解码会选不同 token 的位置**（大约只占全部生成位置的 **4%**）才借用 RL 版的 token，其余都用基座版自己的选择——结果**找回了 RL 版 90.5% 的 pass@1 收益**。更夸张的是，**强行让基座模型以一个词「Alright」开头，就能找回约 35% 的 RL 收益**。

**我的看法**：这个结果强烈暗示——至少在数学推理上，RLVR 的很大一部分作用，是把概率质量重新分配到「基座模型其实也能走通、但平时不优先选」的少数关键分叉点上，尤其是开场的「思考姿态」。它更像是在**雕刻一个已有的分布**，而不是**灌入全新的知识**。这与 2025 年「RL 并没有把 pass@k 的能力上限抬高、只是把 pass@1 对齐到 pass@k」的争论一脉相承。对实践者的启示很直接：如果你的基座模型本身在某个领域「采样多次能做对」，RLVR 的性价比极高；如果它「采多少次都做不对」，RLVR 大概率救不了你，该补的是预训练/中训的知识。

### 3.2 多样性塌缩：RLVR 会悄悄把「别的对法」练没

*Preserving Reasoning Diversity via Adaptive Replay*（arXiv:2610.24236，方法名 TAR）指出一个被低估的副作用：**on-policy 的 RLVR 会逐步压制那些语义不同、但同样正确的推理模式**。原因是有限的 on-policy 采样下，一旦某种「对法」被采到的频率变低，它的概率就会被持续挤压，最后几乎再也采不到、也就再也救不回来——这是一种**不可逆的模式坍塌**。TAR 的解法是建一个「基座模型多样正确解」的小记忆库，只在检测到某种模式正被抑制时，才**定向回放**它。

*EDEN*（arXiv:2610.16105）从另一个角度打同一个病：GRPO 用小组采样，重复采样容易得到高度相似的轨迹，组内奖励方差小、相对优势信号弱。EDEN 不改策略更新，而是在**输入侧注入锚定噪声**，让 rollout 探索到策略自身难以到达的方向。

**我的看法**：多样性塌缩是 RLVR 最隐蔽、也最危险的坑。它在训练曲线上看不出来（准确率还在涨），却会让模型越来越「一根筋」，在需要换思路的难题和分布外任务上变脆。这也解释了一个现象——很多经过重度 RL 的模型 pass@1 很高，但 pass@64 不升反降。**启示**：别只盯着 pass@1，训练中要监控输出的熵/多样性，必要时像 TAR 那样把基座的「别的对法」显式保护起来。

### 3.3 信用分配：别再把一个分摊给上万 token

这是最热闹的一条线。GRPO 把末端奖励无差别广播到每个 token，粗得离谱。几种新思路：

- **ProbePO**（arXiv:2610.24515）：把问题重述为「有预算的测量」——在有限的 rollout 预算下，该去评估哪些**中间状态**？它用一个无需奖励的不确定性分数挑出关键的部分解，在受限的续写预算下估计它们的期望验证奖励，然后**重新分配**（而不是替换）GRPO 的轨迹级优势，同时保持每条轨迹的平均 token 优势不变。
- **HP-RLVR（Hindsight-Privileged RLVR）**（arXiv:2610.20497）：**单条 rollout 就能做 token 级信用分配**，不依赖分组采样。它用「一条已完成轨迹自己的未来 + 验证结果」作为事后特权信息，给每个 token 打更新权重——顺带解决了「一组全对/全错导致信号为 0」的 GRPO 痛点。
- 还有一批工作（如 token 级重要性采样 + proximal KL 正则，arXiv:2610.18738；以及各种自蒸馏 LEAD，arXiv:2610.18256）在给 token 级信用提供更密的监督。

**我的看法**：信用分配是 RLVR 从「能用」走向「高效」的关键一跳。GRPO 的粗颗粒在简单题上够用，但在长链条、多步工具调用、Agent 任务里，「哪一步是关键决策」的信息量极大，粗分配等于把这些信息全扔了。我更看好 **HP-RLVR 这类不依赖分组、单轨迹就能细粒度打分**的路线，因为它同时省算力（不用一题采一大组）又抗 0 信号，工程上更友好。

### 3.4 算力账：挑对题、缩短 rollout

RLVR 很贵，贵在要生成海量长 rollout。于是另一条线专门抠算力：

- **LIFT**（arXiv:2610.24229）：训练前先**挑有价值的 prompt**。它发现一个扎心细节——用完整贪心 rollout 估计 prompt 价值的老方法里，有 **26%～32% 的 rollout 根本没在预算内跑完**。LIFT 改用**部分 rollout**（一个受 pointwise $\mathcal{V}$-information 启发的分数）就能识别出高价值 prompt，省掉大量无效生成。
- **CCR（Concurrent Constraint Reinforcement，Batched Contextual Reinforcement II）**（arXiv:2610.22887）：直问「RLVR 到底需不需要长 rollout 窗口？」。单题 rollout 若在出答案前被截断，组内准确率优势就归零；CCR 把**三道各自可验证的题塞进一次受限的训练续写**里，先答完的题仍保留信用，共享的预算天然鼓励更短但有用的推理——相当于不加显式长度惩罚就压短了链条。

**我的看法**：这条线最被低头刷榜的人忽视，却最影响真实成本。推理模型最大的开销不在参数量，而在「每条样本都要生成好几千 token 再乘以一大组采样」。谁能在不掉点的前提下把 rollout 预算砍一半，谁就能用同样的卡训出两倍的数据。LIFT 的「别在没用的 prompt 上烧算力」和 CCR 的「别养成废话长推理」是两个正交且都很务实的方向。

## 四、应用场景

- **数学 / 竞赛推理**：RLVR 的发源地与最佳适配区，答案天然可验证。
- **代码生成与修复**：用单元测试当验证器，奖励信号客观且密集，是继数学之后最成熟的 RLVR 领域。
- **工具调用 / Agent**：任务是否完成往往可程序化判定（订到票、查到结果、通过回归测试），正成为 RLVR 的新主战场，也最吃信用分配和长 rollout 的苦。
- **结构化抽取 / SQL / 可判定 QA**：只要结果能被规则或执行环境校验，就能套 RLVR。
- **安全对齐**：已有工作（如 Rethinking GRPO for safety alignment）把可验证的安全约束纳入奖励。

共同前提只有一句话：**你的任务存在一个便宜、可靠、难被钻空子的自动验证器**。没有它，RLVR 就退化回要训奖励模型的老路。

## 五、优缺点

**优点**

- 奖励客观、几乎不可伪造，大幅抑制 reward hacking；
- 标注成本极低、可规模化（有答案/测试即可）；
- GRPO 扔掉 critic，训练轻、显存省、实现简单；
- 能在不加监督微调的情况下自发激发推理行为（R1-Zero）。

**缺点与风险**

- **信用分配粗**：末端标量摊给上万 token，长链条上尤其浪费信息；
- **多样性塌缩**：悄悄练没「别的对法」，pass@k 和分布外泛化受损，且往往不可逆；
- **组内信号归零**：一组全对/全错时该样本白采；
- **算力昂贵**：长 rollout × 大采样组，成本主要在生成端；
- **适用面受限于可验证性**：开放式写作、主观质量这类没有自动验证器的任务，RLVR 直接用不上；
- **「天花板」存疑**：若基座模型采多少次都做不对，RLVR 很难无中生有。

## 六、与同类方案对比

| 维度 | RLHF（奖励模型 + PPO） | 拒绝采样微调 / Best-of-N SFT | RLVR（GRPO 等） |
|---|---|---|---|
| 奖励来源 | 学出来的奖励模型（会漂移、会被钻空子） | 用验证器筛出的正样本做 SFT | 验证器直接判 0/1 |
| 标注成本 | 高（人工偏好对） | 中（要生成+筛选） | 低（有答案/测试即可） |
| 是否要 critic | PPO 要价值网络 | 不要（就是 SFT） | GRPO 不要 |
| 探索能力 | 中 | 弱（只学已有正样本） | 强（on-policy 持续探索） |
| 多样性 | 中 | 容易过拟合到少数解 | 易塌缩（本文重点） |
| 典型适配 | 对话、风格、开放式偏好 | 快速冷启动、蒸馏 | 数学/代码/可验证推理 |

**我的看法**：RLVR 不是要取代 RLHF，两者的适用域基本不重叠——**凡是对错可自动判定的，用 RLVR；凡是只能靠人主观偏好的（语气、安全、风格），还得靠 RLHF 或规则奖励**。实践中最强的配方往往是组合拳：先用拒绝采样 SFT 冷启动、再用 RLVR 拉推理、最后用偏好类奖励收口对齐。把 RLVR 当银弹去套开放式任务，是我见过最常见的误用。

## 七、给读者的可落地收获

1. **先验「值不值得 RL」**：对目标任务做 pass@k 探针——基座模型多采几次若能做对，RLVR 性价比高；若怎么采都不对，先补预训练/中训知识，别指望 RL 救场（见 §3.1）。
2. **默认 GRPO 起步**：扔掉 critic、实现简单，是 2026 年最稳的默认选择；但要正视它信用粗、信号易归零两个短板。
3. **一定要监控多样性，不只看 pass@1**：训练中跟踪输出熵/pass@k，发现塌缩就引入定向回放（TAR 思路）或输入侧探索（EDEN 思路）（见 §3.2）。
4. **信用分配按任务难度升级**：简单题用 GRPO 够了；长链条、Agent、多步工具调用建议上更细的 token 级信用（HP-RLVR / ProbePO 思路）（见 §3.3）。
5. **把算力花在刀刃上**：训练前用部分 rollout 挑高价值 prompt（LIFT），别在跑不完或学不到东西的样本上烧卡；用并发/受限预算抑制废话长推理（CCR）（见 §3.4）。
6. **先建好验证器**：RLVR 的上限由验证器的「便宜 + 可靠 + 难钻空子」三件事决定，这往往比调 RL 超参更重要。
7. **组合拳而非银弹**：SFT 冷启动 → RLVR 拉推理 → 偏好/规则奖励收口，别用 RLVR 硬套开放式任务。

## 八、结语：从「能跑」到「跑得省而不塌」

如果说 2025 年 RLVR 回答的是「能不能用纯 RL 激发推理」（能，而且惊艳），那么 2026 年这批工作回答的是更难也更务实的三个问题：**RL 究竟改了什么**（可能主要是重排了基座已有的少数关键决策）、**它悄悄弄坏了什么**（多样性）、**怎么用更少的算力做得更好**（信用分配 + 数据/rollout 预算）。

**我的整体判断**：RLVR 不会被某个「新算法」一统天下，而会沿着「更细的信用分配 / 更强的探索与多样性保护 / 更省的算力账」三条线继续分化演进；它的真正价值是把基座模型「采样能偶尔做对」的能力，**稳定、可靠地固化成默认行为**——这既是它的威力，也划定了它的边界。看清这条边界的人，才知道该在 RLVR 上投入，还是先回去补基座。
